# Infrastructure & Operational Hardening Recommendations

_Generated by security-audit Phase 7. This document provides actionable, infrastructure-level hardening steps that cannot be remediated directly in source code. Review each recommendation and apply to your production/hosting environment._

---

## 1. Network & Edge Security

### Edge Protection & WAF (e.g., Cloudflare, AWS WAF, Azure Front Door, Fastly)
- [ ] **Web Application Firewall (WAF):** Deploy a WAF in front of web endpoints. Enable managed OWASP Top 10 rule sets and rate-limiting rules for login/auth endpoints.
- [ ] **DDoS Mitigation:** Verify unmetered L3/L4/L7 DDoS protection is active at the edge.
- [ ] **Origin Shielding:** Restrict origin server access strictly to CDN/WAF IP ranges (use security groups or Cloudflare Authenticated Origin Pulls). Do not expose origin IPs directly.

### Transport Layer Security (TLS/SSL) & DNS
- [ ] **Minimum TLS Version:** Enforce TLS 1.2 minimum (TLS 1.3 recommended). Disable legacy protocols (SSLv3, TLS 1.0, TLS 1.1) and weak cipher suites.
- [ ] **HSTS Preload:** Configure `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` at the edge reverse proxy and submit domain to [hstspreload.org](https://hstspreload.org/).
- [ ] **Certificate Automation:** Ensure auto-renewal via ACME / Let's Encrypt / AWS ACM with alerts for expiration < 15 days.
- [ ] **DNS Security:** Enable DNSSEC on domain registrar. Set CAA records restricting certificate issuance to authorized CAs only.

## 2. Infrastructure Security Headers (Edge/Reverse Proxy Layer)

Ensure the following headers are injected by your edge proxy (Nginx, Caddy, Cloudflare Workers, AWS CloudFront) for all HTML responses:

```nginx
# Example Nginx / Reverse Proxy Header Configuration
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; object-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'self';" always;
add_header X-Frame-Options "DENY" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=(), payment=()" always;
```

## 3. Secrets Management & Credential Hygiene

- [ ] **Production Secrets Vault:** Migrate production secrets out of `.env` files and environment variables into a managed vault (AWS Secrets Manager, GCP Secret Manager, HashiCorp Vault, Doppler).
- [ ] **Credential Rotation:** Establish an automated 90-day rotation schedule for API keys, database credentials, and service account tokens.
- [ ] **Least-Privilege Service Accounts:** Audit cloud IAM roles. Ensure database, storage, and API credentials use minimal scoped permissions (e.g., read-only where write is not needed).
- [ ] **Git Secret Scanning:** Enable GitHub Secret Scanning / Push Protection or Gitlab Secret Detection to prevent accidental secret pushes.

## 4. Email Security (For Domains Sending or Receiving Mail)

- [ ] **SPF Record:** Publish strict SPF record (`v=spf1 include:_spf.google.com ~all` or provider equivalent).
- [ ] **DKIM Signing:** Enable DKIM key signing for outbound emails.
- [ ] **DMARC Policy:** Enforce `p=reject` or `p=quarantine` with `rua` reporting configured to monitor spoofing attempts:
  ```dns
  _dmarc.yourdomain.com. IN TXT "v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@yourdomain.com; pct=100"
  ```

## 5. Monitoring, Alerting & Incident Response

- [ ] **Centralized Logging (SIEM):** Ship application logs, access logs, and auth events to a secure log aggregator (Datadog, AWS CloudWatch Logs, Splunk, ELK).
- [ ] **Security Alerts:** Set up realtime alerts for:
  - Spike in 401/403 HTTP status codes (brute-force / enumeration probe)
  - Admin login from unexpected location/IP
  - Failed database queries / unhandled exceptions
  - Unrecognized IAM role creation or secret access
- [ ] **Vulnerability Disclosure Policy (`security.txt`):** Deploy a `/.well-known/security.txt` file (RFC 9116) detailing security contact info and disclosure policy:
  ```http
  Contact: mailto:security@yourdomain.com
  Expires: 2027-01-01T00:00:00.000Z
  Preferred-Languages: en
  Canonical: https://yourdomain.com/.well-known/security.txt
  ```
- [ ] **Incident Response Readiness:** Document emergency contacts, rollback procedures, and a breach response checklist.

## 6. Supply Chain & CI/CD Pipeline Hardening

- [ ] **Automated Dependency Updates:** Enable Dependabot / Renovate with automated PR creation for security patches.
- [ ] **Pipeline Permission Scoping:** Enforce `permissions: read-all` in GitHub Actions workflows and explicitly grant minimal permissions per job.
- [ ] **Branch Protection:** Require signed commits, mandatory PR approvals, and passing security status checks before merging to `main` / `master`.
- [ ] **Artifact Verification:** Sign container images and releases using Cosign / Sigstore.

## 7. Platform & Environment-Specific Hardening

<!-- Tailor this section based on project deployment type identified in Phase 0 -->

### Container / Kubernetes Deployments
- [ ] Run containers as non-root (`USER 10001`)
- [ ] Mount root filesystem as read-only (`readOnlyRootFilesystem: true`)
- [ ] Drop all unnecessary Linux capabilities (`capabilities: drop: ["ALL"]`)
- [ ] Enable Seccomp / AppArmor profiles

### Serverless / Cloud Functions (AWS Lambda, GCP Cloud Functions)
- [ ] Enforce minimal IAM role execution policy per function
- [ ] Set strict function execution timeouts (prevent runaway bill attacks)
- [ ] Use VPC Service Controls / Private Link for database access

### Desktop / Mobile / Embedded (if applicable)
- [ ] Enable OS-level sandbox flags and code signing
- [ ] Obfuscate release binaries where intellectual property protection is required
- [ ] Strip debug symbols from production build outputs
